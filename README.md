### Вычислительный расчет

Дано: матрица 1000х1000, размер одного элемента u64 – 8 байт.<br>
В памяти матрица имеет линейное представление, порядок хранения – строчный, строки матрицы следуют одна за другой последовательно. <br>
При проходе по строкам, то есть sequential access, элементы перебираются последовательно, как они лежат в памяти.<br>
При проходе по столбцам, то есть stride access, необходимо во внутреннем цикле «прыгать» по памяти с шагом, равным размеру строки матрицы, то есть 1000 * 8 байт = 8000 байт.
В одной кэш-линии помещается 8 элементов матрицы.<br>
Общее количество элементов – 1_000_000.<br>
Объем полезных данных – 1_000_000 * 8 байт = 8 МБ.<br>
В случае прохода по строкам эффективной является вся кэш-линия с 8 элементами матрицы в ней. Количество используемых кэш-линий – 1_000_000 / 8 = 125_000.<br> 
Соответственно бесполезного трафика – 0 МБ.<br>
В случае прохода по столбцам в одной кэш-линии полезным является только 1 элемент матрицы. Количество используемых кэш-линий – 1_000_000.<br> 
Тогда общий объем загруженных данных – 1_000_000 * 64 байта = 64 МБ.<br>
Бесполезный трафик – 64 МБ – 8 МБ = 56 МБ.<br>

| Параметр           | Проход по столбцам | Проход по строкам | 
| :------------------| :-------------     | :---------------- | 
| Кэш-линий          | 1_000_000          | 125_000           |
| Полезные данные    | 8 МБ               | 8 МБ              |
| Бесполезный трафик | 56 МБ              | 0 МБ              |
| Эффективность      | 12.5 %             | 100 %             |

**Вывод**<br>
Проход по столбцам загружает из памяти в 8 раз больше кэш-линий – соответственно почти в 8 раз больше кэш-промахов, чем при проходе по строкам при том же объёме полезных данных.<br> 
Это приводит к тому, что 87.5% всего трафика (56 МБ из 64 МБ) тратится впустую на пересылку байтов, которые никогда не будут использованы программой.<br> 
В этом случае можно строго говорить об отличной пространственной локальности при проходе по строкам.<br>
Помимо этого процессор поддерживает набор AVX2.<br> 
Последовательный проход дает идеальный паттерн доступа к памяти, что позволяет компилятору векторизировать код для обработки сразу 4 элементов uint64 за одну инструкцию.<br>
Таблица "Измеренные метрики" наглядно подтверждает преимущества подхода с проходом по строкам над подходом с проходом по столбцам, теория совпадает с практикой.
